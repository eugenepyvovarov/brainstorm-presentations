AI Agent Team + Self-Improving Loop

From Machina / @EXM7777 (~4k bookmarks). Build a 5-agent business team on Claude Code, Codex, Hermes, wired through a shared room (Raft) with a self-improving review loop.

Bottleneck was never the model — it was the structure around it.

1. Why one assistant fails You become the QC bottleneck
1. Why one assistant fails You become the QC bottleneck

A single assistant has a structural problem: you are its quality control. Output scales with your attention. More sessions without shared state = competing plans and rediscovery.

You are still the quality control Output scales with your attention
More sessions makes it worse No shared memory → competing drafts
Parallel agents rediscover the same work Nothing learned is shared
Goal: persistent coworker, not chat app Third interface after web + install
2. What a real team needs Four traits that beat a pile of chats
2. What a real team needs Four traits that beat a pile of chats

Four things separate a real team from a pile of agents. Anthropic research: split work + lead review → 90.2% ahead of same model alone. Their product team: agent creates ~65% of code.

Persistent identity Named role, not a fresh session
Compounding memory Each agent diverges into a specialist
Reviewer ≠ author Second agent assumes the work is broken
Shared room Not five chats with you as copy-paste
Measured gain: ~90% ahead with lead review Anthropic multi-agent research signal
3. The shared room (Raft) Where agents see each other’s work
3. The shared room (Raft) Where agents see each other’s work

Raft = Slack-like workspace for humans + agents. Agents claim tasks, run in parallel, review in threads. Agents run on your machine via Computer; use your existing model subs. Free tier covers this build.

Looks like Slack for agents Channels, threads, tasks, DMs
Agents run on your hardware Computer process; files & subs stay local
Use subs you already pay for Claude Code, Codex, Gemini CLI, Cursor…
Hermes joins as external agent Gateway process into the same room
Proof: 20k+ builders; Raft runs on Raft 10 humans + 100+ named agents

Map one named agent to each core business function. Names are examples — copy the routing.

Lead acquisition — June Watch sources, qualify, draft first touch
Content creation — Cole Everything the audience reads

Service delivery — Ray Work clients pay for
Finance — Penn Invoices, costs, month-end truth
5. Three engines Claude Code · Codex · Hermes
5. Three engines Claude Code · Codex · Hermes

Engine = the harness the agent lives in. Not a new platform — tools you may already run. Team inherits their upgrades forever.

Claude Code = the writer Content + delivery; Fable for hard, cheap for routine
Habits: /loop + /goal Scheduled rounds + explicit finish line
Codex = the builder Workflows, scripts, glue tools; prove with output
Hermes = the night shift Heartbeats, monitors, playbooks; always-on
Routing table to copy June/Etta→Hermes · Cole/Ray→Claude · Penn→Codex
6. Hire one specialist Name, soul, memory, goals, heartbeat
6. Hire one specialist Name, soul, memory, goals, heartbeat

Every agent = same five parts. Example: June (lead acquisition). Full hire: one name, a few chat messages, a couple of schedules — files grow from use.

Name: real, not agent-2 Routing + audit trail
Soul: role, scope, tone, hard rules Accumulates in chat; ~half page bar
Memory: MEMORY.md + notes You feed corrections; compress past a page
Goals: own / done / escalate Said once; agent keeps them
Heartbeat: schedules without asking June: 07:00 sweep + hourly silent reply check
7. Self-improving loop No agent grades its own work
7. Self-improving loop No agent grades its own work

Rule: no agent grades its own work. Reviewers are the same five pointed at each other. Everything lands as draft; you are final call on sends/money/clients. Rejections write back → self-improving.

Rule: no self-grading Author will always approve itself
Reviewer assumes work is broken Wrong fit, weak reason, stale source…
Same five review each other Cole↔Ray, June↔Etta, Penn↔Cole
Drafts only leave the room You approve sends, money, client work
Rejections → soul + memory files Same mistake doesn’t survive twice
8. First week playbook One pillar at a time
8. First week playbook One pillar at a time

Don’t stand up five agents day one — a team you can’t feed is theater. Week 1 feels slower (you’re writing down judgment); week 4 looks different because of it.

Day 1: install + one channel + ONE agent Pick the pillar that costs the most hours
Day 1: set soul (chat or file) Scope and hard rules swapped in
Day 2: add reviewer + route both Short “assume it’s broken” instruction
Days 3–7: run the pair daily Same mistake twice → write into soul
Week 2: add next pillar only if first runs alone One pillar at a time forever
Playbook: 5 pillars · 3 engines · 5 parts · 1 loop · 1 room Structure was the bottleneck
