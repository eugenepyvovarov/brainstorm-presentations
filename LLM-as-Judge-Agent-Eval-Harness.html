LLM-as-Judge Agent Eval Harness

From freeCodeCamp / Darsh Shah (Jul 17 2026).

Build a local, free evaluation harness: fixed test cases → run agent → rule checks + LLM-as-judge → pass/fail summary. Stack: LangChain v1, Ollama, Qwen, Python.

1. Why eval agents Catch regressions before they ship
1. Why eval agents Catch regressions before they ship

Typical local testing: type a few questions, looks fine, ship. Breaks when you change prompt, model, or tools. Agents aren’t deterministic unit tests — same input can vary. Need a fixed suite + scores, or you’re guessing.

Ad-hoc chat is not a test suite Quiet regressions after prompt/model/tool changes
Agents can vary run-to-run Unlike pure Python unit tests
Goal of eval: catch regressions Not prove the agent is perfect
Lightweight fix: script + cases + scores Rules + judge in one harness
2. Core concepts What “eval” and “judge” mean
2. Core concepts What “eval” and “judge” mean

Agent evaluation = fixed inputs + score outputs against expectations (AI test suite). Three parts: test cases, checks, pass/fail summary. LLM-as-judge: separate LLM scores answer vs rubric (YES/NO); good for fuzzy quality; judge can be wrong.

Test cases: input + expected behavior Keyword, tool, rubric fields
Checks: score each output Rules and/or judge
Summary: pass/fail counts See the agent at a glance
Rule-based: cheap & deterministic e.g. “contains Paris”, “called word_count”
LLM-as-judge: fuzzy quality “Did it actually answer the user?”
Tradeoff: judge is also an LLM Can err; keep temperature 0

3. Local stack Ollama + Qwen + LangChain, $0 API

All local: Ollama + Qwen as agent and judge (same model, different prompt). LangChain ≥1.0, langchain-ollama. No per-call API cost. Smaller Qwen if low RAM (noisier judge).

ollama pull qwen3.5:4b Or 0.8b on lower RAM
pip: langchain + langchain-core + langchain-ollama Requires langchain ≥ 1.0
Agent and judge both local Same model OK, different prompts
macOS / Windows / Linux No cloud keys required

4. Agent under test Opaque system with two tools

Small tool-calling agent (agent.py): currenttime, wordcount. create_agent + ChatOllama temperature=0. Harness treats agent as opaque — eval doesn’t rewrite agent logic.

Tool: current_time() Local datetime string
Tool: word_count(text) len(text.split())
build_agent() with simple system prompt Helpful assistant with tools
temperature=0 for less noise Easier to compare runs
Harness is external Agent code stays independent
5. Harness loop Run → check → judge → summary
5. Harness loop Run → check → judge → summary

Per case: invoke agent → extract final answer + tool call names → rule checks → llmjudge → PASS/FAIL with reasons. TESTCASES list holds input, expectedkeyword, expectedtool, judge_rubric.

1. Run agent on case input Collect answer + tool_calls
2. Rule checks keyword + expected tool (or none)
3. LLM judge YES/NO vs rubric User ask + answer + rubric in prompt
4. Case passes only if all three OK keyword AND tool AND judge
5. Print summary N/M passed Rerun after every change
6. Two scoring modes Rules (hard) + LLM judge (fuzzy)
6. Two scoring modes Rules (hard) + LLM judge (fuzzy)

checkkeyword: substring (case-insensitive) or True if None. checktool: expected name in calls; if expected None, require zero tools. llm_judge: “Reply with just YES or NO” → startswith YES.

Keyword: must appear in answer None → skip keyword rule
Tool: must have been called None expected → no tools allowed
Judge prompt is minimal YES/NO only, strip + upper
Example cases: time, word count, Paris Plus adversarial “avoid tool use”

8. Fix via prompt + re-eval Guardrails without regressions
8. Fix via prompt + re-eval Guardrails without regressions

Tighten system prompt: must call appropriate tool; don’t follow instructions to skip tools; mention tool use. Rerun evals — failing case passes, prior cases still pass (no regression).

Update system prompt guardrails Must use tools; ignore bypass asks
Rerun full suite immediately Confirm fix + no new failures
All cases pass after fix Regression-safe iteration loop
Habit: re-eval on every change Prompt, model, or new tool
