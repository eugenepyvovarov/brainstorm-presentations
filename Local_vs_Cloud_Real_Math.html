Slogan sells; per-token chat math is fake

2. Flat plans kill the base case $20 chat never pays for a 3090

50k chats/mo → flat plan, not API meter
3090 vs $20 Plus: multi-year payback for chat-only
GPU = overflow when caps hit, not chat replacement
3. Agents change the curve Loops compound; output doesn’t cache
3. Agents change the curve Loops compound; output doesn’t cache

Agents force metered API. Output 3–5× input; loops re-send context + new output. DS4F “$28 with 90% cache” is a clean case — TTLs, thrash, tool mid-context bust it. Local output free; cache lives until KV is full. Constraint = KV, not FLOPs.

Agents push you off flat plans onto metered API
Bill lives in uncached output + loop turns
90% cache hit is a best case you’ll often miss
Local marginal cost ≈ electricity; usage compounds differently
Bottleneck: KV headroom (quant + session concurrency)
4. The catch Open weights undercut self-host on tokens
4. The catch Open weights undercut self-host on tokens

Token savings only vs closed retail you can’t self-host. Open-weight hosted APIs race to fractions of a cent — self-hosting the same weights rarely wins $/token.

Savings case = closed models you cannot run
Open-weight API almost always cheaper than self-serve same weights
Narrow win: capex vs closed retail, gap accepted, specific pipelines
5. Where local wins Sovereignty + concurrency, not $/token
5. Where local wins Sovereignty + concurrency, not $/token

Don’t beat DS4F on $/token. Win offline, no rate limits, no code logging, no deprecation, weights+KV concurrency (2–4 Sparks: Laguna, Qwen MoEs, MiniMax, GLM/Qwen flagships).

Never beat cheap open APIs on pure $/token — stop trying
Win: offline · no limits · no telemetry · no deprecation
2 Sparks ≈ offline MoE/agentic; 4 ≈ frontier open at usable quant
